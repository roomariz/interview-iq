## Cause and correction

The failed overlay compared the configured Redis URL after appending `/` against
the request URL as a literal string. HTTPX preserves the missing root slash in
requests made by the existing async quota/admission code. The resulting mismatch
blocked Redis egress and correctly produced a fail-closed 503 before inference.

`deployment/redis_endpoint_guard.py` now supplies one policy for sync transport, async
transport and budget commands. It validates before normalising; Python's
[URL parser does not itself validate endpoints](https://docs.python.org/3/library/urllib.parse.html#url-parsing-security).
The allowed identity is `(https, lowercase DNS hostname, effective port, /)`:

- Empty root path and `/` are equivalent. Explicit `:443` and omitted HTTPS port
  are equivalent. A non-default configured port must match exactly.
- Reject different hosts, schemes, effective ports and non-root paths. No suffix
  matching, wildcard hosts, DNS alias resolution, path-prefix matching or broad
  removal of slashes. Double slashes and encoded paths remain rejected.
- Reject URL user information, query/fragment delimiters, control/space characters,
  malformed hosts and invalid ports. Invalid configuration also fails closed.
- Permit Redis POSTs only. Preserve bearer headers/body and force redirects off
  in both transport paths; an authorised endpoint cannot redirect elsewhere.
- No changes to authentication, visitor tokens, quota algorithms, lease ownership,
  scoring, normal app startup, dependency pins or other provider implementations.

| Hosted verification / metadata-audit HTTP | At most 20 / 20; never an unbounded loop |

Use a new run ledger and stable synthetic visitor identity; shared quotas and
leases remain untouched. Run expiry, kill switch and atomic reservations are
mandatory, including for retries and ambiguous failed calls.

Hosted preflight must pass source-inventory, protection, authentication, valid
context, schema rejection and managed quota/lease checks **before opening inference**.
The valid-context check specifically exercises the formerly rejected async Redis
URL shape. A failure closes the run; do not substitute an endpoint or bypass quotas.

Record attempt counts, per-attempt/workflow latency, retries, schema validity,
provider errors, actual token counts, free-request usage and zero cost privately.
Local safe fallback is not proof of successful live generation. Missing usage or
cost is unknown, not zero. The strict prompt cap may reject evaluation after model
evidence expands its input; do not increase it automatically to complete a run.

Stop immediately on unavailable free route, changed pricing/billing, unsupported
controls, quota denial, unrecoverable provider/schema failure or a budget boundary.
No model/provider switch or extra deployment. If the free route is unavailable,
skip live Free-model verification and prepare mocked the next mocked verification step; the next mocked verification step deployment requires approval.
